## 💡 xPsiphon چیست؟

**xPsiphon یک سرور لینوکس را به مجموعه‌ای از پروکسی‌های Psiphon تبدیل می‌کند که می‌توانید همه را از یک منوی ساده مدیریت و کنترل کنید.**

‏Psiphon یک ابزار رایگان است که ترافیک اینترنت شما را از طریق سرورهایی در سراسر جهان تونل می‌کند. xPsiphon روی سرور لینوکسی شما **برای هر کشور یک تونل Psiphon اختصاصی** اجرا می‌کند — همگی به‌صورت هم‌زمان و هرکدام روی پورت مجزای خود — و یک پنل ساده و کاربردی برای روشن (Start)، خاموش (Stop)، مشاهده وضعیت و تست آن‌ها در اختیارتان قرار می‌دهد.

برای کار با آن **نیازی نیست** متخصص باشید. اگر بتوانید یک دستور را کپی و پیست (Paste) کنید، به‌راحتی می‌توانید آن را نصب کنید. تمامی مراحل زیر گام‌به‌گام و برای افراد مبتدی نوشته شده‌اند.

## 🖥️ قدم ۱ — تهیه یک سرور

شما به یک سرور کوچک لینوکسی (یک VPS) نیاز دارید. تقریباً هر سرور ارزانی مناسب است.

- **سیستم‌عامل:** هر توزیع مدرن لینوکس که دارای `systemd` باشد. اوبونتو 22/24 و دبیان بیشترین میزان تست را داشته‌اند؛ همچنین نصب‌کننده به‌طور خودکار پکیج‌منیجر پیش‌فرض را در Fedora، RHEL 8+، AlmaLinux، Rocky Linux، CentOS 7، openSUSE، Arch Linux، Manjaro و Alpine شناسایی کرده و استفاده می‌کند. **تنها معماری x86_64** — باینری‌های هسته Psiphon در پروژه اصلی فقط برای x86_64 کامپایل شده‌اند.
- **پایتون:** نسخه ۳.۸ یا جدیدتر. اسکریپت نصب‌کننده نسخه واقعی را بررسی می‌کند و در توزیع‌هایی که همچنان پکیج قدیمی `python3` دارند (مانند RHEL/AlmaLinux 8، openSUSE Leap 15 و CentOS 7)، نسخه جدیدتر (`python39` / `python311`) را نصب کرده و آن را در قالب `python3` در دسترس قرار می‌دهد.
- **مشخصات سرور:** ارزان‌ترین و کوچک‌ترین پلن نیز کاملاً کافی است (حتی ۱ هسته پردازنده و ۵۱۲ مگابایت رم پاسخگوی کار است).
- **دسترسی:** ورود با کاربر `root` (یا کاربری که دسترسی `sudo` دارد).

> **نکته درباره Alpine:** اسکریپت نصب‌کننده مبتنی بر bash است و Alpine به‌صورت پیش‌فرض با `ash` عرضه می‌شود و bash ندارد؛ بنابراین پیش از اجرای دستور یک‌خطی، باید bash نصب شده باشد:
>
> ```bash
> apk add --no-cache bash curl
> ```
>
> پس از آن، دستور استاندارد یک‌خطی بدون مشکل اجرا می‌شود (نصب‌کننده همچنین بسته `procps` را نصب می‌کند تا جدول پروسه‌ها کامل باشد).

</div>

```bash
ssh root@YOUR_SERVER_IP
```

<div dir="rtl">

به‌محض مشاهده خط فرمان سرور، به قدم دوم بروید.

## 📥 قدم ۲ — نصب xPsiphon

این دستور را کپی کنید، در ترمینال سرور خود پیست نمایید و کلید Enter را بزنید:

</div>

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/IzumiRain/xPsiphon/main/install.sh)
```

<div dir="rtl">

همین! نصب‌کننده تمام مراحل را به‌صورت خودکار برای شما انجام می‌دهد:

- ✅ در صورت نیاز بسته‌های `curl`، `ca-certificates` و `python3` را نصب می‌کند
- ✅ موتور هسته Psiphon را دانلود می‌کند
- ✅ دستور اصلی `xpsiphon` **و** میانبر کوتاه `xp` را نصب می‌کند
- ✅ تمامی فایل‌های کانفیگ لوکیشن‌ها را می‌سازد (حالت خودکار `AUTO` + ۲۸ کشور مختلف)
- ✅ دایرکتوری‌های لاگ، داده‌ها و run را آماده‌سازی می‌کند

پس از پایان نصب، با دستورات زیر از درستی کارکرد آن اطمینان حاصل کنید:

</div>

```bash
xp version      # باید چاپ کند: xPsiphon 2.1.0
xp doctor       # باید خطوط سبز رنگ OK را نمایش دهد
```

<div dir="rtl">

> 💡 **می‌خواهید با هر بار روشن شدن سرور، سرویس‌ها به‌صورت خودکار اجرا شوند؟** پارامتر `--enable-autostart` را به انتهای دستور نصب اضافه کنید، یا بعداً هر زمان خواستید دستور `sudo xp autostart on` را اجرا نمایید.

## ▶️ قدم ۳ — اجرای یک لوکیشن

ساده‌ترین و بهینه‌ترین گزینه حالت `AUTO` است که به سایفون اجازه می‌دهد خودکار بهترین و پرسرعت‌ترین سرور را برای شما انتخاب کند:

</div>

```bash
sudo xp start AUTO
```

<div dir="rtl">

بررسی وضعیت اجرای لوکیشن:

</div>

```bash
xp status
```

<div dir="rtl">

کشور خاصی مد نظرتان است؟ کافی است از کد دورقمی آن کشور استفاده کنید (به [فهرست کامل لوکیشن‌ها](#-لوکیشن%E2%80%8Cها-و-پورت%E2%80%8Cها) مراجعه فرمایید):

</div>

```bash
sudo xp start US      # ایالات متحده آمریکا
sudo xp start DE      # آلمان
sudo xp start all     # اجرای هم‌زمان تمام لوکیشن‌ها
```

<div dir="rtl">

هر لوکیشن روی **پورت‌های محلی مستقل خود** شنود می‌کند. به عنوان مثال:

</div>

```text
AUTO  →  SOCKS 127.0.0.1:1080   |  HTTP 127.0.0.1:8080
US    →  SOCKS 127.0.0.1:1101   |  HTTP 127.0.0.1:8101
```

## 🎛️ منو (پنل تعاملی)

ترجیح می‌دهید به‌جای تایپ دستورات از یک منوی تصویری استفاده کنید؟ فقط کافی است تایپ کنید:

</div>

```bash
xp
```

<div dir="rtl">

پنلی برای شما باز خواهد شد که تنها با فشردن یک کلید می‌توانید:

- 📊 وضعیت کامل تمام سرویس‌ها و منابع سرور را ببینید
- ▶️ لوکیشن `AUTO` را روشن کنید، یا لوکیشن دلخواه را Start / Stop / Restart نمایید
- ⏯️ همه لوکیشن‌ها را با هم روشن یا خاموش کنید
- 📜 لاگ زنده یک لوکیشن را مشاهده کنید (Live Tail)
- 🔁 اجرای خودکار هنگام بوت (Autostart) را فعال یا غیرفعال کنید
- 🔌 سرویس HTTP API را مدیریت نمایید (مشاهده وضعیت / روشن / خاموش)
- 🔧 پورت‌های SOCKS یا HTTP هر لوکیشن را تغییر دهید
- 🧱 وضعیت فایروال و پورت‌های باز را بررسی کنید
- 📶 تست پینگ و سرعت دانلود بگیرید
- 🩺 بررسی‌های سلامت سیستم (Doctor) را اجرا کنید
- ⬆️ برنامه xPsiphon را به‌روزرسانی نمایید
- 🗑️ برنامه xPsiphon را حذف کنید

دستورات `xpsiphon` و `xp` کاملاً یکسان هستند — از هرکدام که راحت‌تر هستید استفاده کنید.

## ⌨️ جدول دستورات سریع

</div>

| دستور | عملکرد |
| --- | --- |
| `xp` | باز کردن پنل تعاملی |
| `xp status` | نمایش وضعیت سرور و تمامی نمونه‌های فعال Psiphon |
| `xp locations` | فهرست تمام لوکیشن‌ها، پورت‌ها و مسیر فایل‌های کانفیگ |
| `sudo xp start AUTO` | روشن کردن لوکیشن خودکار (Auto) |
| `sudo xp start US` | روشن کردن یک لوکیشن کشوری خاص |
| `sudo xp start all` | روشن کردن هم‌زمان تمامی لوکیشن‌ها |
| `sudo xp stop US` | خاموش کردن یک لوکیشن خاص |
| `sudo xp stop all` | خاموش کردن تمامی لوکیشن‌ها |
| `sudo xp restart US` | راه‌اندازی مجدد (Restart) یک لوکیشن |
| `xp logs US` | نمایش آخرین خطوط لاگ یک لوکیشن |
| `xp logs US -f` | مشاهده لاگ زنده و لحظه‌ای لوکیشن |
| `sudo xp port US --socks 1201 --http 8201` | تغییر پورت‌های یک لوکیشن |
| `xp firewall` | بررسی پورت‌های محلی و قوانین فایروال UFW/firewalld |
| `xp ports` | دستور معادل برای `xp firewall` |
| `xp test` | تست پینگ و سرعت تمام لوکیشن‌های در حال اجرا |
| `xp test AUTO` | تست یک لوکیشن خاص |
| `xp speed US` | دستور معادل برای `xp test US` |
| `xp doctor` | بررسی پیش‌نیازها و سلامت کلی نصب |
| `sudo xp autostart on` / `off` | فعال / غیرفعال کردن اجرای خودکار هنگام بوت سیستم |
| `xp autostart status` | مشاهده وضعیت اجرای خودکار هنگام بوت |
| `sudo xp api start` | نصب و راه‌اندازی سرویس سیستمی HTTP API |
| `xp api status` | نمایش وضعیت API، آدرس شبکه و دستور تست نمونه |
| `xp api serve` | اجرای API در پیش‌زمینه (بدون systemd) |
| `sudo xp api stop` | متوقف‌سازی و حذف سرویس API |
| `sudo xp update` | به‌روزرسانی درجا (بدون تغییر کانفیگ‌ها و بدون قطعی تونل‌ها) |
| `sudo xp uninstall` | حذف xPsiphon (حفظ فایل‌های کانفیگ و باینری هسته) |
| `sudo xp uninstall --purge` | حذف **کامل همه فایل‌ها** |
| `xp version` | نمایش نسخه فعلی نصب‌شده |

<div dir="rtl">

> 🔐 دستوراتی که سرویسی را روشن/خاموش می‌کنند یا تغییراتی روی سیستم می‌دهند نیاز به دسترسی `sudo` دارند. دستورات فقط‌خواندنی (`status`، `locations`، `logs`، `test`، `doctor` و ...) نیازی به دسترسی روت ندارند.

## 🌍 لوکیشن‌ها و پورت‌ها

حالت `AUTO` از سیستم انتخاب خودکار هوشمند Psiphon استفاده می‌کند:

</div>

```text
AUTO SOCKS: 127.0.0.1:1080     AUTO HTTP: 127.0.0.1:8080
```

<div dir="rtl">

هر کشور روی پورت‌های **اختصاصی، ثابت و بدون تداخل** خود اجرا می‌شود تا بتوانید چندین کشور را هم‌زمان روشن داشته باشید:

</div>

```text
AT SOCKS 1081 / HTTP 8081     JP SOCKS 1095 / HTTP 8095
BE SOCKS 1082 / HTTP 8082     NL SOCKS 1096 / HTTP 8096
BG SOCKS 1083 / HTTP 8083     NO SOCKS 1097 / HTTP 8097
CA SOCKS 1084 / HTTP 8084     PL SOCKS 1098 / HTTP 8098
CH SOCKS 1085 / HTTP 8085     RO SOCKS 1099 / HTTP 8099
CZ SOCKS 1086 / HTTP 8086     SE SOCKS 1100 / HTTP 8100
DE SOCKS 1087 / HTTP 8087     US SOCKS 1101 / HTTP 8101
DK SOCKS 1088 / HTTP 8088     AU SOCKS 1102 / HTTP 8102
EE SOCKS 1089 / HTTP 8089     ES SOCKS 1103 / HTTP 8103
FI SOCKS 1090 / HTTP 8090     ID SOCKS 1104 / HTTP 8104
FR SOCKS 1091 / HTTP 8091     IE SOCKS 1105 / HTTP 8105
GB SOCKS 1092 / HTTP 8092     LT SOCKS 1106 / HTTP 8106
IN SOCKS 1093 / HTTP 8093     RS SOCKS 1107 / HTTP 8107
IT SOCKS 1094 / HTTP 8094     SG SOCKS 1108 / HTTP 8108
```

<div dir="rtl">

فهرست این کشورها (**۲۸ منطقه خروجی Egress Region**) مستقیماً با **کلاینت زنده و فعال Psiphon** راستی‌آزمایی شده است — دقیقاً همان مجموعه `AvailableEgressRegions` که هسته `psiphon-tunnel-core` روی همین کانال ارتباطی اعلام می‌کند.

> 🧩 **لوکیشن‌های قدیمی (Legacy):** کدهای `BG` (بلغارستان) و `EE` (استونی) صرفاً جهت سازگاری با نسخه‌های گذشته نگه داشته شده‌اند اما در حال حاضر در سرورهای فعال سایفون موجود نیستند. در صورت استفاده نشدن کاملاً بی‌خطرند (لوکیشنی که سروری برای آن نباشد صرفاً وصل نمی‌شود). برای حذف آن‌ها می‌توانید فایل‌های `/etc/psiphon/configs/psiphon.BG.config` و `/etc/psiphon/configs/psiphon.EE.config` را پاک کنید.

> 🔒 **پایداری شماره پورت‌ها در تمام به‌روزرسانی‌ها:** لوکیشن‌های جدید در آپدیت‌ها همواره اولین پورت‌های آزاد بعدی را استفاده می‌کنند و پورت‌های موجود جابه‌جا نمی‌شوند؛ بنابراین رول‌های فایروال شما دست‌نخورده باقی مانده و همیشه کار خواهند کرد.

## 🔧 تغییر پورت یک لوکیشن

پورت هر لوکیشن در فایل کانفیگ مستقل خودش قرار دارد. اگر یک پورت پیش‌فرض در سرور شما اشغال باشد (مثلاً برنامه دیگری از `1092` استفاده کند)، می‌توانید به‌راحتی آن را تغییر دهید:

</div>

```bash
sudo xp port GB --socks 1201 --http 8201
sudo xp port GB --socks 1201          # فقط پورت SOCKS تغییر می‌کند و HTTP دست‌نخورده می‌ماند
```

<div dir="rtl">

همچنین می‌توانید این کار را از درون پنل تعاملی با کلید `p) Change location port` انجام دهید. xPsiphon از انتخاب پورت‌های متداخل یا خارج از محدوده استاندارد جلوگیری می‌کند. در صورتی که آن لوکیشن روشن باشد، برای اعمال پورت‌های جدید باید یک‌بار آن را ری‌استارت کنید:

</div>

```bash
sudo xp restart GB
```

</div>

```text

<div dir="rtl">

</div>

xp logs AUTO       # مشاهده آخرین خطوط لاگ

```

## 🧱 فایروال و پورت‌های باز

بررسی اینکه کدام پورت‌ها در حال شنود هستند و فایروال سرور شما چه قوانینی دارد:

</div>

```bash
xp firewall
```

<div dir="rtl">

این دستور موارد زیر را گزارش می‌دهد:

- آزاد بودن یا در حال شنود بودن هریک از پورت‌های SOCKS و HTTP
- وضعیت سرویس فایروال UFW و قوانین باز بودن پورت‌ها
- وضعیت سرویس firewalld و پورت‌های مجاز تعریف‌شده در آن

## 📶 تست پینگ و سرعت

تست لوکیشن‌های فعال از طریق پروکسی SOCKS خودشان:

</div>

```bash
xp test           # تست عملکرد تمامی لوکیشن‌های فعال
xp test AUTO      # تست لوکیشن اتوماتیک
xp speed US       # میانبر برای: xp test US
```

<div dir="rtl">

تنها لوکیشن‌هایی که **روشن و فعال** هستند تست می‌شوند. لوکیشن‌های خاموش وضعیت `not listening` نشان می‌دهند.

گزینه‌ها و پارامترهای پیشرفته:

</div>

```bash
xp test AUTO --no-speed
xp test US --timeout 30
xp test AUTO --url https://www.gstatic.com/generate_204
xp test AUTO --speed-url https://speed.cloudflare.com/__down?bytes=1048576
```

<div dir="rtl">

> ℹ️ توجه داشته باشید مقدار «پینگ» گزارش‌شده در اینجا، مدت‌زمان تأخیر یک درخواست HTTPS **از داخل پروکسی تونل‌شده** است، نه پینگ سنتی ICMP.

## 🔁 اجرای خودکار هنگام بوت (Autostart)

برنامه xPsiphon می‌تواند با بالا آمدن و ریبوت سرور، تمام لوکیشن‌های کانفیگ‌شده را خودکار راه‌اندازی کند:

</div>

```bash
sudo xp autostart on       # فعال‌سازی اجرای خودکار هنگام بوت
sudo xp autostart off      # غیرفعال‌سازی
xp autostart status        # مشاهده وضعیت فعال بودن
systemctl status xpsiphon.service
```

## 🔌 HTTP API

تمام قابلیت‌هایی که در پنل ترمینالی وجود دارد از طریق یک وب‌سرویس سبک مبتنی بر JSON و HTTP نیز در دسترس است؛ بنابراین می‌توانید xPsiphon را از طریق اسکریپت‌ها، داشبوردهای تحت وب یا سایر اپلیکیشن‌ها کنترل کنید. این API تنها با کتابخانه استاندارد پایتون پیاده‌سازی شده و نیازی به هیچ وابستگی یا کتابخانه اضافه‌ای ندارد.

### راه‌اندازی

</div>

```bash
sudo xp api start          # نصب و اجرا به‌صورت سرویس سیستمی systemd (روش پیشنهادی)
xp api status              # نمایش وضعیت، آدرس شبکه و دستور تست نمونه
sudo xp api restart        # ری‌استارت سرویس
sudo xp api stop           # متوقف‌سازی و حذف سرویس
xp api serve               # اجرا در پیش‌زمینه (با Ctrl-C متوقف می‌شود؛ بدون systemd)
```

<div dir="rtl">

به‌طور پیش‌فرض این وب‌سرویس فقط روی **`127.0.0.1:8900`** شنود می‌کند (تنها حلقه لوپ‌بک محلی) تا از شبکه اینترنت در دسترس نباشد. برای تغییر آدرس یا پورت می‌توانید از فلگ‌های `--host` و `--port` استفاده کنید:

</div>

```bash
sudo xp api start --host 127.0.0.1 --port 9000
```

<div dir="rtl">

> ⚠️ بایند کردن سرویس روی یک آدرس عمومی (`--host 0.0.0.0`) باعث دسترسی به API از سطح شبکه می‌شود. این کار را صرفاً همراه با فایروال محدود به IPهای معتبر و مطمئن انجام دهید و همواره با توکن امنیتی مانند یک رمز عبور مهم رفتار کنید.

### احراز هویت

تمامی درخواست‌ها به API نیازمند ارسال توکن هستند. این توکن در نخستین راه‌اندازی تولید شده و در فایل `/etc/psiphon/api-token` با سطح دسترسی امن `0600` ذخیره می‌شود. توکن باید در هدر درخواست ارسال شود — به دلایل امنیتی **هیچ امکانی برای ارسال توکن در URL وجود ندارد**، زیرا توکن در URL از طریق فایل `/proc/<pid>/cmdline` برای تمام کاربران محلی سرور قابل‌مشاهده بوده و در تاریخچه شل نیز ثبت می‌شود:

</div>

```bash
TOKEN=$(sudo cat /etc/psiphon/api-token)

curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8900/api/status
curl -s -H "X-Api-Token: $TOKEN"          http://127.0.0.1:8900/api/status
```

<div dir="rtl">

درخواست‌های فاقد توکن معتبر پاسخ `401 Unauthorized` دریافت می‌کنند و ارسال بیش از حد درخواست‌های ناموفق از یک آدرس منجر به دریافت خطای `429 Too Many Requests` (محدودیت نرخ ارسال) خواهد شد. با تنظیم متغیر محیطی `XPSIPHON_API_TOKEN` می‌توانید توکن ذخیره‌شده روی دیسک را بازنویسی کنید (برای چرخش توکن بدون دستکاری فایل‌ها مفید است) — مقدار متغیر محیطی همواره اولویت بالاتری دارد.

### اندپوینت‌ها

</div>

| متد | اندپوینت | کارکرد |
| --- | --- | --- |
| `GET` | `/` | فهرست تمامی اندپوینت‌های در دسترس |
| `GET` | `/api/version` | نسخه برنامه و منبع به‌روزرسانی |
| `GET` | `/api/status` | وضعیت کامل سرور به همراه وضعیت تک‌تک لوکیشن‌ها |
| `GET` | `/api/locations` | فهرست لوکیشن‌های کانفیگ‌شده، پورت‌ها و مسیر کانفیگ‌ها |
| `GET` | `/api/logs/{LOC}?lines=100` | نمایش انتهای فایل لاگ یک لوکیشن (حداکثر تا ۲۰۰۰ خط) |
| `GET` | `/api/autostart` | وضعیت اجرای خودکار هنگام بوت |
| `GET` | `/api/doctor` | اجرای بررسی‌های سلامت سیستم (Doctor) |
| `POST` | `/api/start/{LOC\|all}` | روشن کردن لوکیشن‌ها |
| `POST` | `/api/stop/{LOC\|all}` | خاموش کردن لوکیشن‌ها |
| `POST` | `/api/restart/{LOC\|all}` | راه‌اندازی مجدد لوکیشن‌ها |
| `POST` | `/api/test/{LOC\|all}?timeout=20&no_speed=1` | تست پینگ و سرعت لوکیشن از طریق SOCKS |
| `POST` | `/api/autostart/{on\|off\|toggle}` | فعال یا غیرفعال کردن اجرای خودکار هنگام بوت |
| `POST` | `/api/port/{LOC}` | تغییر پورت‌ها با ساختار: `{"socks": 1201, "http": 8201}` |

<div dir="rtl">

پارامتر `{LOC}` کد لوکیشن است (`AUTO`، `US`، `DE` و غیره). اندپوینت‌هایی که سیستم را تغییر می‌دهند (`start`، `stop`، `restart`، `autostart` و `port`) نیازمند اجرای سرویس با دسترسی root هستند و در غیر این صورت خطای `403 Forbidden` بازمی‌گردانند — وقتی سرویس را با `sudo xp api start` نصب کنید، این شرط برقرار است.

### مثال‌های کاربردی

</div>

```bash
TOKEN=$(sudo cat /etc/psiphon/api-token)
BASE=http://127.0.0.1:8900

# چه لوکیشن‌هایی هم‌اکنون فعال هستند؟
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/status" | python3 -m json.tool

# روشن کردن تمامی لوکیشن‌ها
curl -s -X POST -H "Authorization: Bearer $TOKEN" "$BASE/api/start/all"

# تغییر پورت‌های لوکیشن آمریکا
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"socks":1201,"http":8201}' \
  "$BASE/api/port/US"

# دریافت ۵۰ خط آخر لاگ لوکیشن AUTO
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/logs/AUTO?lines=50"
```

<div dir="rtl">

متغیرهای محیطی قابل تنظیم برای API:

</div>

```bash
XPSIPHON_API_HOST=127.0.0.1        # آدرس بایند
XPSIPHON_API_PORT=8900             # شماره پورت
XPSIPHON_API_TOKEN_FILE=/etc/psiphon/api-token
XPSIPHON_API_TOKEN=...             # توکن دلخواه (بر فایل ارجحیت دارد)
```

## ⬆️ به‌روزرسانی

برای به‌روزرسانی نسخه نصب‌شده به آخرین نگارش منتشرشده:

</div>

```bash
sudo xp update
```

<div dir="rtl">

**طراحی به‌روزرسانی‌ها به گونه‌ای است که هیچ اختلالی در عملکرد سرور ایجاد نمی‌کند** — سرویس‌های فعال به فعالیت خود ادامه می‌دهند:

- ✅ فایل‌های کانفیگ موجود شما حفظ می‌شوند، **شامل پورت‌های شخصی‌سازی‌شده**
- ✅ فایل باینری هسته Psiphon بدون تغییر باقی می‌ماند (مجدداً دانلود نمی‌شود)
- ✅ تونل‌های فعال **متوقف نمی‌شوند**؛ وضعیت autostart دست‌نخورده می‌ماند
- ✅ تنها فایل‌های کانفیگ برای لوکیشن‌های **جدید** افزوده می‌شوند

لوکیشن‌های تازه اضافه می‌شوند اما خودکار اجرا نمی‌شوند. هر زمان تمایل داشتید آن‌ها را روشن کنید:

</div>

```bash
sudo xp start all
```

<div dir="rtl">

دستورات اختیاری جهت دریافت مجدد بخش‌ها (این موارد ممکن است موقتاً سرویس را تحت تأثیر قرار دهند):

</div>

```bash
sudo xp update --force-psiphon    # دانلود مجدد فایل باینری هسته
sudo xp update --force-configs    # بازنویسی کامل کانفیگ‌ها (پورت‌های شخصی‌سازی‌شده ریست می‌شوند)
```

<div dir="rtl">

همچنین می‌توانید از درون پنل تعاملی (کلید `u) Update xPsiphon`) یا با اجرای مجدد اسکریپت نصب یک‌خطی، به‌روزرسانی را انجام دهید — رفتار همه آن‌ها کاملاً یکسان و ایمن است.

> 📝 دستور `xp update` فایل‌ها را از شاخه `main` گیت‌هاب دریافت می‌کند. برای اطلاع از تغییرات نسخه‌ها به [CHANGELOG](CHANGELOG.fa.md) مراجعه فرمایید.

## 🗑️ حذف نصب

حذف کامل xPsiphon با یک دستور ساده:

</div>

```bash
sudo xp uninstall
```

<div dir="rtl">

این دستور تمام لوکیشن‌ها را خاموش می‌کند، سرویس `xpsiphon.service` را غیرفعال و حذف می‌نماید، فایل‌های اجرایی `xpsiphon` و `xp` را پاک کرده و دایرکتوری‌های زمان اجرا (`/run/xpsiphon`، `/var/log/xpsiphon` و `/tmp/psiphon`) را حذف می‌کند. به‌صورت پیش‌فرض فایل‌های کانفیگ و باینری Psiphon در دایرکتوری `/etc/psiphon` **نگه‌داشته می‌شوند**.

حذف **کامل همه‌چیز**، از جمله فایل‌های کانفیگ و باینری هسته:

</div>

```bash
sudo xp uninstall --purge
```

<div dir="rtl">

حذف بدون پرسش پیام تأیید (مناسب برای اسکریپت‌های اتوماسیون):

</div>

```bash
sudo xp uninstall --yes
sudo xp uninstall --purge --yes
```

<div dir="rtl">

همچنین می‌توانید از درون پنل تعاملی با کلید `x) Uninstall xPsiphon` فرآیند حذف را انجام دهید.

<details>
<summary>پاک‌سازی دستی (در صورتی که دستور <code>xp</code> از قبل پاک شده باشد)</summary>

```bash
sudo systemctl disable --now xpsiphon.service 2>/dev/null || true
sudo rm -f /etc/systemd/system/xpsiphon.service
sudo systemctl daemon-reload 2>/dev/null || true
sudo rm -f /usr/local/bin/xpsiphon /usr/local/bin/xp
sudo rm -rf /run/xpsiphon /var/log/xpsiphon /tmp/psiphon
sudo rm -rf /etc/psiphon   # تنها در صورتی که مایلید فایل‌های کانفیگ و باینری نیز پاک شوند
```

## 🗂️ مسیرها

مسیرهای پیش‌فرض سیستم:

</div>

```text
Psiphon binary: /etc/psiphon/psiphon-tunnel-core-x86_64
Configs:        /etc/psiphon/configs
Data roots:     /tmp/psiphon
Logs:           /var/log/xpsiphon
PID files:      /run/xpsiphon
Systemd unit:   /etc/systemd/system/xpsiphon.service
API unit:       /etc/systemd/system/xpsiphon-api.service
API token:      /etc/psiphon/api-token
```

<div dir="rtl">

متغیرهای محیطی برای تغییر مسیرها در زمان اجرا:

</div>

```bash
XPSIPHON_BIN=/path/to/psiphon-tunnel-core-x86_64
XPSIPHON_CONF_DIR=/path/to/configs
XPSIPHON_DATA_DIR=/path/to/data
XPSIPHON_LOG_DIR=/path/to/logs
XPSIPHON_RUN_DIR=/path/to/run
XPSIPHON_SERVICE_PATH=/etc/systemd/system/xpsiphon.service
XPSIPHON_API_SERVICE_PATH=/etc/systemd/system/xpsiphon-api.service
XPSIPHON_API_TOKEN_FILE=/etc/psiphon/api-token
```

<div dir="rtl">

تنظیمات اختیاری زمان اجرای Go برای پروسه‌های تونل (**به‌صورت پیش‌فرض غیرفعال است**):

</div>

```bash
XPSIPHON_GOGC=50                 # درصد هدف Garbage Collector (پیش‌فرض: مقدار استاندارد Go)
XPSIPHON_GOMEMLIMIT=45MiB        # محدودیت نرم حافظه برای هر پروسه تونل
```

<div dir="rtl">

این تنظیمات عمداً به‌صورت اختیاری (Opt-in) قرار داده شده‌اند. مقادیر پیش‌فرض زبان Go یک نقطه شروع کاملاً پایدار و مطمئن هستند؛ کاهش `GOGC` یا اعمال یک `GOMEMLIMIT` فشرده، در ازای مصرف کمتر حافظه رم، **مصرف پردازنده (CPU) بیشتری** به همراه دارد که می‌تواند کارایی سرورهای کوچک یا تک‌هسته‌ای را کاهش دهد. در صورت نیاز، پیش از راه‌اندازی متغیرهای `XPSIPHON_*` را در محیط شل ست کنید یا آن‌ها را به فایل سرویس systemd اضافه نمایید و سپس دستور `sudo xp restart all` را اجرا کنید. در صورت تنظیم، این مقادیر در واحد autostart نیز اعمال می‌شوند تا پس از ریبوت نیز همان رفتار حفظ شود. مقدار صریح `XPSIPHON_*` همیشه بر مقادیر ارث‌برده‌شده `GOGC`/`GOMEMLIMIT` اولویت دارد.

متغیرهای سفارشی‌سازی اسکریپت نصب‌کننده:

</div>

```bash
XPSIPHON_INSTALL_PATH=/usr/local/bin/xpsiphon
XPSIPHON_SHORT_PATH=/usr/local/bin/xp
XPSIPHON_GITHUB_REPO=IzumiRain/xPsiphon
XPSIPHON_GITHUB_REF=main
```

<div dir="rtl">

## 🔐 مدل امنیتی

‏xPsiphon با **دسترسی کاربر root** اجرا می‌شود (روشن و خاموش کردن تونل‌ها به این دسترسی نیاز دارد)؛ بنابراین معماری و طراحی امنیتی پروژه بر مبنای محافظت از این سطح دسترسی بنا شده است. خلاصه نکات امنیتی — با جزئیات کامل در [SECURITY.md](SECURITY.md):

- **تنها رابط تحت شبکه، وب‌سرویس HTTP API است** که به‌طور پیش‌فرض تنها روی آدرس محلی `127.0.0.1` شنود می‌کند. تمام درخواست‌ها ملزم به ارسال توکن هستند (تنها از طریق هدر — امکان ارسال توکن در URL به عمد حذف شد، چرا که توکن‌های موجود در URL از طریق فایل `/proc/<pid>/cmdline` برای تمام کاربران محلی سرور قابل‌خواندن بودند)؛ همچنین تلاش‌های ناموفق مکرر از یک آدرس IP با پاسخ `429` محدود (Throttle) می‌شوند.
- **توکن API ارزشی معادل دسترسی کاربری root دارد.** این توکن با ۱۹۲ بیت آنتروپی رمزنگاری تولید شده، با مجوز دسترسی امن `0600` ذخیره می‌گردد و مقایسه آن به‌صورت زمان ثابت (Constant-time) انجام می‌شود. با آن همانند یک رمز عبور حیاتی رفتار کنید؛ جهت تغییر و چرخش توکن (Rotate) می‌توانید فایل آن را حذف کرده یا متغیر محیطی `XPSIPHON_API_TOKEN` را مقداردهی کنید.
- **اعمال سندباکس حفاظتی systemd** برای هر دو سرویس (`ProtectSystem=strict`، `NoNewPrivileges`، `MemoryDenyWriteExecute` و محدودسازی مسیرها با `ReadWritePaths`)، تا بروز هرگونه باگ احتمالی در اسکریپت مدیر یا پروسه تونل، منجر به دسترسی نوشتن روی کل فایل‌سیستم نشود. در عین حال، عملکرد عادی اتصال تونل‌ها تحت این سندباکس حفظ می‌شود.
- **اعتبارسنجی دایرکتوری‌های زمان اجرا** — اسکریپت مدیر از پذیرش پوشه داده‌ای که کاربر دیگری از قبل در `/tmp` ایجاد کرده باشد خودداری می‌کند (این یک روش حمله محلی شناخته‌شده علیه سرویس‌های دارای دسترسی root است).
- **بررسی سلامت فایل‌های دانلودی پیش از اجرا** — قبل از اینکه باینری با دسترسی root اجرا شود، اندازه فایل و هدر اجرایی ELF/x86-64 آن اعتبارسنجی می‌شود. اسکریپت نصب، کدها را از طریق ارتباط امن TLS از گیت‌هاب دریافت می‌کند؛ چنانچه زنجیره تأمین کاملاً ثابتی مد نظر شماست، می‌توانید `XPSIPHON_GITHUB_REF` را روی یک برچسب (Tag) مشخص قفل کنید.

> 🔎 آیا باگ یا مشکل امنیتی پیدا کرده‌اید؟ به بخش [گزارش آسیب‌پذیری](#-گزارش-آسیب%E2%80%8Cپذیری) مراجعه کنید — لطفاً از ثبت گزارش‌های امنیتی در Issueهای عمومی خودداری فرمایید.

لطفاً مشکلات و باگ‌های امنیتی را به‌صورت **محرمانه** و از طریق بخش [گزارش محرمانه آسیب‌پذیری در گیت‌هاب](https://github.com/IzumiRain/xPsiphon/security/advisories/new) در این مخزن گزارش دهید.

لطفاً اطلاعات زیر را در گزارش خود بگنجانید: نسخه آسیب‌پذیر (`xp version`)، نام و نسخه توزیع لینوکس، عملیاتی که انجام دادید، نتیجه‌ای که انتظار داشتید و در صورت امکان یک سناریوی بازتولید حداقلی (Minimal reproduction). ظرف چند روز گزارش شما بررسی و تأیید خواهد شد و نام شما در فهرست تغییرات (Changelog) ثبت خواهد شد، مگر آنکه مایل باشید ناشناس بمانید.

لطفاً برای مواردی که فکر می‌کنید قابل سوءاستفاده هستند **به هیچ وجه** Issue عمومی باز نکنید و روی سرورهایی که مالک آن‌ها نیستید هیچ تستی انجام ندهید.

## 🩹 عیب‌یابی و رفع اشکال

<details>
<summary>خطای <code>Psiphon binary not found</code></summary>

نصب‌کننده را مجدداً اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/IzumiRain/xPsiphon/main/install.sh)
```

</details>

<details>
<summary>نمایش <code>not listening</code> در تست سرعت</summary>

ابتدا لوکیشن مورد نظر را روشن کنید، سپس تست بگیرید:

```bash
sudo xp start AUTO
xp test AUTO
```

</details>

<details>
<summary>خطاهای مربوط به مجوز دسترسی (Permission errors)</summary>

دستورات مربوط به Start، Stop، Restart و autostart نیاز به دسترسی root دارند:

```bash
sudo xp start AUTO
sudo xp stop all
```

</details>

<details>
<summary>بررسی سلامت و وضعیت کلی سیستم</summary>

```bash
xp doctor
xp status
xp locations
```

</details>

<details>
<summary>پاسخ خطای <code>401</code> یا <code>403</code> در API</summary>

خطای `401` نشان‌دهنده ارسال نشدن یا نادرست بودن توکن احراز هویت است — توکن را مطابق بخش [HTTP API](#-http-api) ارسال کنید. خطای `403` یعنی اندپوینت مربوطه نیاز به دسترسی root دارد: سرویس API را با دستور `sudo xp api start` نصب کنید، یا با دستور `sudo xp api serve` اجرا نمایید.

جهت اطمینان از فعال بودن سرویس و مشاهده توکن:

```bash
xp api status
sudo cat /etc/psiphon/api-token
```

</details>

## ✨ امکانات

- نصب آسان با یک دستور روی سرور خام اوبونتو
- پشتیبانی نصب‌کننده از چندین توزیع مختلف لینوکس (apt، dnf، yum، zypper، pacman، apk)
- پنل ترمینالی تعاملی و کاربرپسند
- میانبر کوتاه خط فرمان: `xp`
- لوکیشن خودکار `AUTO` روی پورت‌های SOCKS `1080` و HTTP `8080`
- **۲۸** لوکیشن کشوری روی پورت‌های یکتا و مجزا (راستی‌آزمایی‌شده با کلاینت زنده سایفون)
- امکان شخصی‌سازی پورت‌های SOCKS و HTTP برای هر لوکیشن (از طریق CLI یا پنل)
- قابلیت روشن (Start)، خاموش (Stop) و راه‌اندازی مجدد (Restart) یک لوکیشن یا تمامی آن‌ها
- نمایش وضعیت جامع سرور شامل مصرف کلی و مصرف CPU/RAM به ازای هر پروسه Psiphon
- تفکیک فایل لاگ اختصاصی برای هر لوکیشن
- ابزار بررسی وضعیت پورت‌ها و فایروال برای UFW و firewalld
- تست پینگ و سرعت دانلود اختصاصی برای هر لوکیشن از طریق پروکسی SOCKS مربوطه
- به‌روزرسانی درجا، کاملاً امن و بدون قطعی در سرویس‌های فعال
- حذف تمیز و کامل برنامه (به‌همراه گزینه اختیاری پاک‌سازی کامل purge)
- قابلیت راه‌اندازی خودکار هنگام بوت سیستم با `systemd` (اختیاری)
- **HTTP API مبتنی بر JSON** با احراز هویت توکن جهت کنترل برنامه‌نویسی‌شده
- **بدون نیاز به نصب هیچ‌گونه پکیج یا وابستگی جانبی در پایتون**
